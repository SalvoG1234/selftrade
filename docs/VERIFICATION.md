# Verification ledger

Every row below is a **command that was actually run and its output**, kept here rather than on
the front page so that `README.md` stays readable without losing a single result. Nothing in this
file is projected, estimated or rounded up; where a command produced an unflattering number, the
number is here.

The rows were produced on **Windows 11 / Git Bash**, originally with Python 3.14.5, and the suite
has since been re-run on Python 3.13.14 in its own virtualenv (the second table below is where
those later rows go). The part that still lives on the front page is the part a reader needs
before trusting any of it: `README.md` → *Verification status* holds the summary,
**Not verified here** and **Known limits**, which are the constraints this ledger does *not*
prove.

Two notes on how to read the tables:

* **A green row is not a product claim.** The default configuration lost money on its own
  out-of-sample window and the critic refused to deploy it; those rows are in here too.
* **`N/D` is a real answer.** Where the program cannot measure something it says so instead of
  filling the cell, and the same rule applies to this file.

### The counts that are measured rather than typed

The size of the suite is quoted in five places (the README, `CONTRIBUTING.md`, this file twice, the
launch kit and the social card), and a hand-typed number repeated five times is a number nobody
owns. The evidence is the first thing this command printed: the five copies said `815` only because
a **manual** pass had just caught them at `809` and typed the new number in by hand — and that pass
never thought to look at the launch kit, which was quoting **`785`** from an even older state and
had been wrong for longer than anyone had noticed. A human eye checking one phrase in one file is
exactly the process that had already failed twice. They are now marked fragments: the
text between a pair of named HTML comments is written by a machine and nothing outside them is ever
touched.

```powershell
python -m selftrade verify --ledger            # collect the suite (~2 s) and hold every count to it
python -m selftrade verify --ledger --write    # repair the counts, then record a real run
python -m selftrade verify --ledger --run      # execute the suite and report, writing nothing
```

Exit **0** when every count agrees with the measurement, **1** when one has drifted (the message
names the file, the line and both numbers), **2** when the suite cannot be measured at all. It is a
step in CI, so a change that adds tests and leaves five documents claiming the old number fails the
build rather than aging quietly.

Three details worth knowing:

* **`--write` runs the suite twice, on purpose.** This file's numbers are enforced *by* the suite, so
a run started while the documents are stale goes red — a tool that waited for a green suite could
never repair the state it exists to repair. So it collects first (two seconds, and the fragment it
writes, *"N tests collected"*, is true if only weaker), and the run after that is green.
* **A fragment that names another interpreter is a dated record**, not a claim about today. The
3.13 row below says which interpreter produced it, `--write` refuses to overwrite it from 3.14 (that
would turn a real record into a claim about a run that never happened), and the 3.13 job in CI is
what enforces it. The check prints every such record it skipped, so none of them is invisible.
* **`docs/LOOP-AI-PLAN.md` is exempt on the record.** It declares itself a historical snapshot with
an in-band comment, because its counts describe the tree as it was when the plan was written.
Rewriting them would be a worse lie than leaving them; the declaration is reported on every run.

The research numbers in this file — the holdout Sharpe, the drawdown, the cost drag — are
**not** generated, and that is deliberate. They are outputs of `evolve`, `invest` and `stress`, they
cost minutes to recompute, and each row already names the command that produced it. A generator for
them would be a second and weaker source of truth. What is measured here is the one number that is a
pure function of the working tree, which is the one that goes stale without anyone noticing.
